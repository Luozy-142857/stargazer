# Stargazer

**斜视 / 集合不足 的眼动测量内核 + 分视训练游戏（本地 demo）**

普通摄像头 + MediaPipe 面部关键点 + 分眼岭回归校准，实时给出**双眼相对偏斜角（棱镜度 PD）**、注视稳定性（BCEA）和水平追随增益；导出的会话文件可以拿去和临床金标准做 Bland–Altman 一致性分析。

产品分**两种模式**：受试者打开页面看到的是简化训练流程（使用模式），开发者加 `?mode=debug` 进入完整测量与验证台。详见下面[「两种模式」](#两种模式)。

---

## 一句话定位

这是**测量内核 + 验证台 + 一个训练游戏**，不是器械。

- ✅ 有：摄像头采集、13 点分眼校准、留出验证误差（诚实的精度读数）、偏斜/注视/追随/重复性/立体视五项测量、棱镜对照采集、指标导出、离线一致性分析工具、分视训练游戏（火箭追星星）。
- ❌ 没有：账号体系、MySQL、报告 PDF、医学结论。这些在测量可信之后再接（见文末路线图）。

## 它不是什么

| 常见误解 | 实际情况 |
|---|---|
| 「替掉眼动仪」 | 可见光摄像头没有角膜反光（Purkinje I）通道，做不到商用眼动仪的 <1°。1.5° 只在**个人校准 + 头位受控 + 小角度**下可达 |
| 「能测单眼抑制」 | **测不到**。抑制是皮层双眼现象，视频里没有可观测信号。必须换成行为学范式（对比度平衡点、随机点立体图） |
| 「传视频到后端分析」 | 不做。全部推理在浏览器本地，导出文件里只有派生数值，没有一帧图像 |

## 指标口径

| 指标 | 单位 | 定义 | 实现 |
|---|---|---|---|
| 偏斜角 | PD（棱镜度） | 单眼估计视轴与当前靶点方向之差，`PD = 100·tan(θ)` | `gaze/metrics.ts: signedDeviationDeg` |
| 偏斜事件 | 次 / 占比 | 连续超过 3 PD 且持续 ≥200 ms 的时段 | `metrics.ts: detectDeviationEpisodes` |
| BCEA | deg² | 注视散点的双变量椭圆面积，`A(p) = −2πσ₁σ₂ln(1−p)` | `metrics.ts: bcea` |
| 注视段 | 段 / 时长 | I-DT 法，100 ms 窗口内离散度 <1° | `metrics.ts: detectFixations` |
| 追随增益 | 无量纲 | 以靶点为自变量的回归斜率，理想 ≈1 | `metrics.ts: pursuitQuality` |

完整定义与临床对应见 [`docs/METRICS.md`](docs/METRICS.md)。

## 快速开始

```bash
npm install --ignore-scripts   # 见下方说明
npm run prepare-assets         # 拷 wasm 运行时 + 下载人脸模型（约 3.7MB，只需一次）
npm run dev
```

打开 `http://localhost:5173`，用 Chrome 或 Edge。

> **为什么是 `--ignore-scripts`**
> 本机沙箱禁止子进程管道，esbuild 的 postinstall 会失败。跳过脚本不影响功能（esbuild 的二进制来自独立平台包）。你自己在普通终端里直接 `npm install` 也没问题。

**在 iPad / 手机上测**：`npm run dev:https`，用自签证书起服务。Safari 会警告证书风险，手动信任即可。原因：`getUserMedia` 只在 `localhost` 或 `https` 下可用，局域网 `http://192.168.x.x` 会被浏览器直接拒绝。

## 两种模式

页面打开默认是**使用模式**（给孩子/家长）；右上角「调试模式 →」或 `?mode=debug` 进入调试模式。选择会记住在本地，不用每次带参数。

| | 使用模式（默认） | 调试模式（`?mode=debug`） |
|---|---|---|
| 给谁 | 受试者、孩子、家长 | 开发者、验证台 |
| 流程 | 欢迎 → 设置 → 坐姿引导 → 校准 → 游戏 → 结算 | 四个面板：几何 / 校准 / 测试 / 导出 |
| 校准 | **一个不少**：热身 + 13 点 + 留出验证 + 漂移点自动重测 + 同一套质量门控 | 同左 |
| 术语 | 全部收起来，结果只有「状态很好 / 还不错 / 建议重试」三档 | 交叉验证、LOO、MDC95、BCEA、PD 全暴露 |
| 测试 | 只有训练游戏（60 秒一局） | 偏斜 / 注视 / 追随 / 重复性 / 立体视 / 棱镜对照全部 8 个协议 |
| 导出 | 结算页一个「保存记录」按钮（浏览器下载） | 输出目录选择、逐帧日志、ground_truth.csv |

两个模式共用同一份核心实现（`src/ui/core.ts`：几何换算、质量门控、校准拟合逐行同一份代码），「使用模式更宽松」不存在——它只是把同一套测量翻译成了人话。

## 使用流程（调试模式）

1. **几何（必须实测）**
   - 屏幕对角线：查显示器规格，或用尺量。
   - 观看距离：**用尺量**，别估。
   - 浏览器缩放保持 100%，否则「毫米/像素」全错。
   - 摄像头抬到**与眼睛同高**。平板平放桌面 = 俯视 = 眼位测量误差显著变大。

2. **启动摄像头** → 等模型就绪（首次几秒）。

3. **校准**（13 点 + 1 个留出点）
   看「**交叉验证**」中位值：<1.5° 良好，1.5–2.5° 可用，>2.5° 请重来。
   交叉验证是每次扣掉一个点重拟合、共 26 次，比单个留出点可靠。
   拟合残差永远比它小，不要拿拟合残差当精度。

4. **三项测试**（每项前都会全屏并提示）
   - 偏斜监测 45s：双眼不动，看中心光点。间歇性外斜视的漂移会在这段时间里自己出现。
   - 注视稳定性 12s。
   - 水平追随 15s。

5. **导出** → 会话 JSON（可选附带逐帧特征）。

6. **一致性分析**

```bash
python tools/validate_offline.py session.json
python tools/validate_offline.py sessions/*.json --gt ground_truth.csv -o out/
python tools/validate_offline.py --self-test      # 公式自检
```

金标准 CSV 只要两列：`case_id,ref_pd`。

## 已知限制

1. **可测范围受校准视野约束**，约 ±13°（±22 PD）。超出范围的偏斜会被**系统性地低估**。大角度恒定性斜视不适用——这类恰好是手术指征，本来也不是训练对象。
2. **符号约定未确证**。当前只报「图像左眼 / 图像右眼」的带符号值，还没有映射成内斜/外斜。必须用棱镜在验证阶段确认后才能对临床下结论。
3. **距离必须实测**。程序用瞳距反推的距离只做合理性校验，不参与角度换算。
4. **30 fps 只够算追随增益**。扫视细节（幅度、峰速）需要 60 fps。
5. **MediaPipe 虹膜点是学出来的先验，不是边缘检测**。大角度偏斜、眯眼、眼镜反光、内眦赘皮都会让它退化。内眦赘皮还会造成假性内斜——这正是产品必须能给出反证的地方。
6. **不做任何医学结论**。输出是测量值，不是诊断。

```

 (getUserMedia)  (MediaPipe)                    (校准学到的)       │
                                                                ▼
                                        靶点已知 ──► 偏斜角(度) ──► PD
                                                                │
                                                                ▼
                                           BCEA / 事件 / 追随增益 ──► 会话 JSON
```

|---|---|---|
| 采集 | `src/vision/face.ts` | MediaPipe 封装、虹膜中心、头位、眨眼基线、质量门控 |

| 指标 | `src/gaze/metrics.ts` | 角度换算、PD、BCEA、注视检测、偏斜事件、追随 |
| 协议 | `src/protocols.ts` | 校准/验证/偏斜/注视/追随的步骤定义（纯数据） |
| 呈现 | `src/ui/runner.ts` | 全屏靶点绘制与时间推进 |
| **双模式核心** | `src/ui/core.ts` | 几何换算、质量门控、校准拟合——调试/使用两个模式共用 |
| 调试模式 | `src/ui/app.ts` | 测量验证台装配（8 个协议、棱镜对照、导出） |
| 使用模式 | `src/ui/usage.ts` | 受试者流程装配（设置 → 校准 → 游戏 → 结算） |
| 预览叠加 | `src/ui/overlay.ts` | 摄像头预览上的虹膜标记（两模式共用） |
| 训练游戏 | `src/game/gazeGame.ts` | 火箭追星星：燃料锚定、one-euro 滤波、磁吸辅助 |
| 分视呈现 | `src/game/presenter.ts` | 红青/红绿/红蓝分视，优势眼对比度压制 |
| 游戏辅助 | `src/game/assist.ts` `gazeFilter.ts` `starSpawn.ts` | 捕获半径/磁吸/滤波/撒点（纯函数，可离线回放断言） |

| 验证台 | `tools/validate_offline.py` | 会话统计、Bland–Altman、CCC、SVG 图、公式自检 |

## 训练游戏：火箭追星星

视线带着火箭飞，追上星星得分。星星一半只给左眼看、一半只给右眼看（红青分视），优势眼那层压暗——这是抗抑制的标准做法。燃料持续消耗，燃料不足时必须飞回屏幕正中的「加油站」补给，补给那一两秒就是一次注视锚定（把校准藏进玩法，见 `gazeGame.ts` 头部注释）。控制链路的误差预算与调参记录见 `docs/GAME-CONTROL-AUDIT.md` 与 `docs/GAME-ASSIST-VERIFY.md`。

**三个刻意的架构决定**

1. **推理只在前端**。视频不出本机 → 未成年人隐私合规的最大捷径，也省掉 GPU 服务器。
2. **相对偏斜角，不是绝对注视点**。两眼共用同一个头位/相机/畸变，这些误差是共模的，一相减就部分抵消。绝对注视点 1.5° 是虚的，偏斜角 1.5° 才是可辩护的。
3. **校准必须留一点**。没有留出验证点，「精度」就只是训练残差，自己骗自己。

**扩展点**：`ui/runner.ts` 的 `overlay` 回调已经是呈现层的抽象边界。接红青眼镜、快门眼镜或 VR 时，只需换呈现实现，测量层不动。
